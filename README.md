# LevelUp · 本地成长管理与数据备份

一个深色科技风、匿名、无需登录的个人成长管理静态网站。
仅使用 HTML、CSS、原生 JavaScript 和 LocalStorage，无第三方依赖、无后端、无数据库、无账号系统。

在线访问：[LevelUp](https://levelup-growth.pages.dev/)。
源码仓库：[still-young/levelup](https://github.com/still-young/levelup)（私有，需要仓库访问权限）。

仓库保存网站源码和运行说明。`work/` 中的测试文件、`outputs/` 中的截图与发布包、个人 JSON 备份不参与版本提交。

## 后续保存修改到 GitHub

在 VS Code 中打开本项目文件夹，再打开终端，依次执行：

```powershell
git status
git add .
git commit -m "更新 LevelUp 网站"
git push
```

提交前先检查 `git status` 中的文件是否都是本次修改的源码。GitHub 保存的是代码版本，个人计划和日志仍保存在浏览器中，需通过 Backup 页面另行备份。

目前 Cloudflare Pages 使用手动上传发布包；推送到 GitHub 后，线上网站不会自动更新。

## 在 VS Code 中运行

1. 打开 VS Code，选择「文件 → 打开文件夹」，选择 `C:\Users\admin\Desktop\levelup`。
2. 点击左侧「扩展」，安装 **Live Server**（作者 Ritwick Dey）。
3. 在文件列表中右键 `index.html`，选择 **Open with Live Server**。
4. 浏览器通常会打开 `http://127.0.0.1:5500/index.html`，以实际显示的地址为准。
5. 修改并保存 HTML、CSS 或 JavaScript，Live Server 会自动刷新页面。

也可以直接双击 `index.html` 查看页面，不需要安装依赖。不过，各浏览器对 `file://` 页面的本地存储处理存在差异，推荐用 Live Server 验证保存功能。

Live Server 只是在你的电脑上提供静态文件预览，不是需要租用、续费的线上服务器。

## 文件结构与阅读顺序

```text
levelup/
├── index.html          Dashboard 的页面内容
├── pages/
│   ├── goals.html      目标管理页面
│   ├── tasks.html      日常任务管理页面
│   ├── journal.html    成长日志管理页面
│   ├── analytics.html  成长统计页面
│   └── backup.html     本地备份、导入预览和恢复
├── css/
│   └── style.css       设计变量、公共布局、卡片、响应式样式
├── js/
│   ├── app.js          公共侧栏、顶栏、图标、日期、手机导航
│   ├── storage.js      本地存储读取和写入
│   ├── goals.js        目标创建、编辑、完成、回收站、筛选
│   ├── tasks-model.js  本地日期、任务统计与筛选规则
│   ├── tasks.js        任务表单、目标关联与列表操作
│   ├── journal-model.js 日志日期、统计、搜索与排序规则
│   ├── journal.js      日志表单、历史列表和回收站
│   ├── analytics-model.js 统计日期、汇总和分组规则
│   ├── analytics.js    时间筛选、趋势图、目标进度与详细表
│   ├── backup.js       JSON 下载、文件检查、预览和恢复
│   └── dashboard.js    寄语表单、字数、保存反馈
├── assets/
│   └── logo.svg        本地图标；欢迎区图形使用 CSS 绘制
└── README.md           本说明
```

建议先阅读 `index.html`，再看 `css/style.css`，最后按页面阅读 JavaScript 文件。样式表顶部 `:root` 中集中定义主题颜色和圆角，修改这些变量可以统一调整全站风格。

`app.js` 把公共导航、顶栏和页脚放进对应的占位容器，避免五个页面分别维护相同代码。页面通过 `<body>` 的 `data-page` 设置当前导航项，通过 `data-root` 设置项目根目录的相对路径。

## 数据导出与导入备份

左侧 **Backup（备份）** 页面可操作，不需要网络服务、账号或数据库。

### 导出

1. 先保存其他页面里尚未保存的文字，再打开 Backup。
2. 核对当前寄语、目标、任务和日志数量。总数包含回收站。
3. 点击「下载备份文件」，在浏览器下载列表中确认 `LevelUp-backup-时间.json` 已保存。
4. 将文件保存在自己记得的位置。它是完整的未加密文字备份，不会自动更新。

### 导入与撤销

1. 可先导出当前数据，以保留独立文件副本。
2. 点击选择文件，选中此前 LevelUp 导出的 JSON（最大 10 MB）。文件只在浏览器内读取，不上传。
3. 检查备份时间，以及当前 / 备份中的数量。所有四类内容都必须完整，支持的版本目前为 1。
4. 勾选「我已核对」，再点击「确认替换并导入」。这是完整替换，不是合并；没有新增的重复记录。
5. 导入后刷新 Dashboard、Goals、Tasks、Journal 或 Analytics 检查恢复内容。
6. 尚未编辑任何数据时，可回到 Backup 点击「撤销本次导入」，恢复导入前的内容。继续保存寄语、目标、任务或日志后，撤销入口关闭，避免撤销时丢失新的修改。

文件格式错误、版本不兼容或数据不完整时，不会执行导入。预览后其他标签页修改了数据时，需要重新预览。浏览器存储不足时整份替换失败，现有数据保留；恢复和撤销都需要可用的存储空间。

### 验证备份

1. 导出备份，再选择同一文件预览，检查数量和备份时间一致。
2. 点击取消，现有数据应不变；选择普通文本文件或错误版本 JSON，应拒绝恢复。
3. 勾选确认并导入，检查各页面的数据和回收站保留；再撤销，检查恢复导入前状态。
4. 再次导入后修改并保存一条寄语，撤销入口应关闭；重新导出应包含这次新修改。

### 代码阅读补充

`storage.js` 统一处理备份验证和写入，复用现有记录校验并只保留已知字段。未导入过数据时，沿用原来的四个存储键。第一次导入后，四类数据统一保存在 `levelup:v1:workspace` 中，以一次 `setItem` 完成替换；原来的四个键不再作为当前数据读取。继续编辑时也通过统一入口更新这个工作区键。

工作区键还会暂存导入前的一份内容供撤销，第一次正常编辑后释放这份撤销内容。它不替代下载的备份文件，清除网站数据会一并删除。公共 `app.js` 将工作区变化通知其他页面重新读取；未保存表单仍会保留。

## 验证成长统计

1. 进入 Analytics，检查任务数、日志篇数是否符合已保存记录，切换最近 7 天、30 天、全部记录。
2. 点击「查看详细数据表」，检查具体日期的数量与趋势图一致；30 天图可在图表内部横向滚动。
3. 回到 Tasks，完成一项任务，再返回 Analytics：对应日期的完成任务数增加；重新开启后减少。
4. 在 Journal 选择过去的日期补写，确认对应日期日志数量增加，而不是都算在创建当天。
5. 同一天完成任务并写两篇日志，活跃天数只增加一天。
6. 回收任务或日志后它不计入统计；恢复后重新计入。完成目标后，目标完成率和对应领域进度变化。
7. 回到 Dashboard，检查近 7 天活跃数据；刷新后统计仍来自已有记录。

### 统计口径

- 任务按实际完成日期计算，计划日期不参与完成数量统计。重新开启的任务不算已完成，再次完成则使用新的完成时间。
- 日志按记录日期计算；活跃天数是「有任务完成或日志记录」的日期去重数。
- 回收站和未来日期不计入活动统计。「全部记录」表示截至今天的全部活动，不包含未来日期日志；Dashboard 的日志总篇数则包含所有未回收日志。
- 目标完成率始终表示当前全部目标的状态，不受活动时间筛选影响。本版没有目标历史快照，因此不展示历史目标完成率。
- 最近 7 / 30 天按日绘图，缺少活动的日期补零。全部记录按有活动的月份汇总，空月份不列出；超过 24 个有活动月份时，图表只显示最近 24 个，顶部汇总和详细表仍包括全部。
- 所有日期按当前设备时区计算。本页的活动统计用于回顾记录，不是对个人能力或成长质量的评分。

## 验证成长日志

1. 进入 Journal，填写标题和正文，保存后刷新，检查日期、文字、感受均保留。
2. 同一天再写一篇：日志总篇数增加，记录天数不增加。选择昨天补写，则记录天数增加。
3. 点击编辑，修改内容并保存；输入多行文字，检查换行保留。
4. 用关键词搜索标题或正文，选择指定日期查看，点击「清除条件」取消搜索和日期限制（保留当前的全部 / 今日 / 回收站选项）。
5. 长日志点击「阅读全文」展开。填写 `<b>保持专注</b>` 应显示原文，不执行 HTML。
6. 移入回收站后，总篇数减少；在回收站恢复后，原日期和正文保留，总篇数恢复。
7. 返回 Dashboard，检查成长记录数量。未填标题、正文或只填空格时，应阻止保存。

日志使用独立键 `levelup:v1:journal`。保存是手动操作，正文下的字数提示不会自动保存草稿；当天记录按日志选择的日期统计，不按实际创建时间统计。

## 验证日常任务

1. 进入 Tasks，添加「完成一道 Java 练习」，选择一个目标，计划日期设为今天。
2. 保存并刷新，检查任务名称、关联目标和日期保留；在「今日计划」中也能找到。
3. 编辑任务，修改名称或日期；标记完成，返回 Dashboard 检查「今日完成任务」增加。
4. 重新开启，今日完成数应减少；再次标记完成会记录新的完成时间。
5. 移入回收站并恢复，检查统计随之更新。回收站不计入统计，恢复保留原完成时间。
6. 将关联目标移入 Goals 回收站，任务应仍存在，并提示目标在回收站；恢复目标后提示恢复正常。
7. 试填只有空格的名称，应提示填写任务名称。

“今日计划”按计划日期计算，包含当天安排的待完成和已完成任务；“今日完成”按实际完成日期计算。没有日期的任务可在全部 / 待完成中找到；本版不发送系统通知。任务保存于 `levelup:v1:tasks`，不会改写寄语和目标的存储键。

## 验证目标管理

1. 进入 Goals，创建「本周完成 Java 练习」，选择「学习」，填写描述和截止日期后保存。
2. 刷新页面，检查目标仍然存在。返回 Dashboard，检查进行中目标数增加。
3. 点击「编辑」，修改名称并保存；点击「标记完成」，检查完成数量增加。
4. 分别切换「进行中」和「已完成」，检查筛选结果；点击「重新开启」，目标回到进行中。
5. 点击「移入回收站」，在回收站找到目标并恢复，检查统计同步变化。
6. 名称只填空格时，应提示填写名称。长文字应自动换行，不撑宽手机页面。

目标保存于 `levelup:v1:goals`，与寄语的 `levelup:v1:daily-note` 分开。升级不修改已有寄语。

## 本地数据须知

寄语、目标、任务和日志保存在当前浏览器、当前网站地址对应的 LocalStorage 中，不会发送到服务器。换浏览器、换设备、切换 `localhost` / `127.0.0.1` 或更改端口，不会共享同一份数据。请在固定预览地址下使用。

清除网站数据会删除全部本地记录（包括回收站）；隐私模式退出后数据也可能被删除。现在可以手动导出和导入备份，但没有自动跨设备同步。LocalStorage 和备份文件都没有加密，匿名也不代表在共享电脑上受到密码保护，请勿写入敏感信息。
